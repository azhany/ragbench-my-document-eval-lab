# RB-11 — Persist traces, token usage, and cost

Part of [Sprint 3 — Traceable chat](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 3 — Traceable chat

**Priority / Size / Owner:** P0 · M · backend

**Depends on:** [RB-10.md](RB-10.md)

## User story

As a reviewer, I can explain an answer's evidence, latency, and estimated cost, including when a request fails.

## Scope

Migrate `rag_traces` and `rag_spans`; record request, query_embedding, retrieval, prompt_build, llm_generation, citation_mapping, and rerank when enabled. Implement trace list/detail APIs; snapshot effective config, ranked evidence, prompt/model/pricing identity, reported usage, and cost components.

## Tasks

- [ ] Add migrations for `rag_traces` and `rag_spans`
- [ ] Record the request, query_embedding, retrieval, prompt_build, llm_generation, citation_mapping, and rerank (when enabled) spans
- [ ] Implement trace list/detail APIs
- [ ] Snapshot effective config, ranked evidence, prompt/model/pricing identity, reported usage, and cost components
- [ ] Compute estimated cost from explicit input/output rates and currency; make unknown pricing or missing provider usage unavailable, not falsely zero, and include the documented embedding/generation components in query totals
- [ ] Give errors correlated traces and structured logs where storage is available
- [ ] Make a trace write failure a structured persistence error, never a fully traceable success, while logs retain correlation

## Acceptance criteria

- [ ] Chat returns its persisted trace ID with latency/tokens/estimated cost; errors also have correlated traces and structured logs where storage is available.
- [ ] Estimated cost uses explicit input/output rates and currency; unknown pricing or missing provider usage is unavailable, not falsely zero. Query totals include the documented embedding/generation components.
- [ ] A trace write failure cannot be reported as a fully traceable success; the client sees a structured persistence error and logs retain correlation.

## Verification

Chat → citations + trace + spans in PostgreSQL; exact token-cost calculations, unknown-profile/missing-usage cases, classified provider error traces, and database failure behavior. Reprocess/delete source and verify historical evidence remains inspectable.

Verification checklist (to be completed during implementation):

- [ ] Chat produces citations, trace, and spans persisted in PostgreSQL
- [ ] Exact token-cost calculations verified
- [ ] Unknown-profile and missing-usage cases verified
- [ ] Classified provider error traces verified
- [ ] Database failure behavior verified
- [ ] Reprocess/delete source, then historical evidence remains inspectable
