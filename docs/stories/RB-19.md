# RB-19 — Compare runs with persisted regression policy

Part of [Sprint 5 — Measurable experiments](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Sprint:** Sprint 5 — Measurable experiments

**Priority / Size / Owner:** P0 · L · backend/evaluation

**Depends on:** [RB-15 — Score retrieval and generation separately](RB-15.md), [RB-17 — Add configurable hybrid retrieval](RB-17.md)

## User story

As an evaluator, I can see whether a candidate regressed against a baseline and which policy rule caused the result.

## Scope

Implement `GET /api/v1/eval-runs/{id}/compare/{baselineId}` and policy persistence. Return baseline/candidate values, absolute/relative deltas, metric direction, threshold, evaluability, and pass/regression reasons without collapsing dimensions into one score.

## Tasks

- [ ] Implement `GET /api/v1/eval-runs/{id}/compare/{baselineId}` in the Go API
- [ ] Persist the regression policy: metric direction, absolute vs relative delta, threshold, and the definition of "quality gain" as explicit inputs
- [ ] Implement compatibility checks on dataset version, source corpus, relevance unit/scoring K, and evaluator policies
- [ ] Return baseline/candidate values, absolute/relative deltas, metric direction, threshold, evaluability, and per-rule pass/regression reasons
- [ ] Handle boundary semantics: strictly greater-than vs equality, zero baseline, missing metrics, and incomplete runs, plus the quality-gain exception for latency/cost
- [ ] Keep a non-comparable or incomplete pair from being labelled a clean pass, and keep quality regression distinct from pipeline/evaluator failure

## Acceptance criteria

- [ ] Compare only compatible dataset versions, source corpus, relevance unit/scoring K, and evaluator policies; differing index settings are allowed when evidence mapping supports a valid comparison.
- [ ] Thresholds are explicit persisted inputs. Test strictly greater-than vs equality, zero baseline, missing metrics, incomplete runs, and the defined quality-gain exception for latency/cost.
- [ ] A non-comparable or incomplete pair cannot be labelled a clean pass. A quality regression and a pipeline/evaluator failure remain distinct.

## Verification

Hand-calculated comparison fixtures exercising every adopted threshold and boundary; API comparison of two actual runs; confirm response explains exactly why each rule passed, failed, or could not be evaluated.
