## User story

As an assessment reviewer, I can observe a simple agent workflow calling named tools in a safe order and producing a concise final report only after extraction and validation are complete.

## Scope

Add a bounded `DocumentIntelligenceAgent` orchestration contract around named tools/functions. Airflow may own asynchronous stage orchestration, while Go retains domain/tool contracts and validation semantics. Avoid a general-purpose agent framework.

## Tasks

- [x] Define named tool interfaces for text extraction, structured extraction, validation, and summary generation
- [x] Enforce stage order: extract -> structured extract -> schema validation -> financial validation -> summary
- [x] Persist stage/tool status and correlation identifiers
- [x] Generate a concise summary using structured data plus validation findings
- [x] Ensure summary clearly reflects material validation warnings/failures instead of hiding them
- [x] Define bounded retry rules by failure class; do not retry deterministic validation failures as model errors
- [x] Return/persist a final result containing document ID, structured data, validation findings, summary, and trace identity
- [x] Add workflow tests for success, extraction failure, LLM malformed output, validation warning, and summary-provider failure
- [x] Update architecture and `ENGINEERING_NOTES.md`

## Acceptance criteria

- [ ] Runtime evidence shows the agent calling the required tools/functions in the documented order. *(Compose/provider runtime gate pending.)*
- [x] Validation always completes before summary generation is accepted as final.
- [x] A stage failure creates a visible failed/partial state with correlation evidence; no later stage silently fabricates success.
- [x] Final successful result includes structured data, validation output, concise summary, and trace/correlation identity.
