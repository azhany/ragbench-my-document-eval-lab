# RB-18 — Execute bounded parameter experiments

Part of [Sprint 5 — Measurable experiments](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Implemented (RB-18). `rag_parameter_sweep` drives the persisted state machine through the Go API; experiments persist the expanded matrix with an explicit combination limit before execution; per-combination immutable config identities are created/reused idempotently; index revisions resolve through `document_reindex` (failed reindex never evaluates against the wrong corpus); partial failures retain run links. Remaining open gate: a live two-config sweep through Airflow (credential-blocked).

**Sprint:** Sprint 5 — Measurable experiments

**Priority / Size / Owner:** P1 · L · pipeline/backend

**Depends on:** [RB-08 — Operate the Library lifecycle](RB-08.md), [RB-14 — Orchestrate durable evaluation runs](RB-14.md), [RB-17 — Add configurable hybrid retrieval](RB-17.md)

## User story

As an evaluator, I can run a small configuration matrix so chunking and query changes are measured systematically.

## Scope

Implement `rag_parameter_sweep`, proposed experiment create/list/detail APIs, and persisted experiment-to-config/run links. Resolve required index revisions through `document_reindex`, then launch evaluations. Support chunk size/overlap, top-k, vector/hybrid, prompt version, and model profile; enable rerank dimension only after RB-25.

## Tasks

- [x] Implement the `rag_parameter_sweep` DAG
- [x] Implement proposed experiment create/list/detail APIs and persisted experiment-to-config/run links
- [x] Resolve required index revisions through `document_reindex` before launching evaluations; prevent evaluation against the wrong corpus after a failed reindex
- [x] Support the configuration matrix dimensions: chunk size/overlap, top-k, vector/hybrid, prompt version, and model profile; reserve the rerank dimension until [RB-25](RB-25.md) lands
- [x] Persist the expanded configuration matrix before execution with an explicit configured combination limit
- [x] Reject invalid/unsupported combinations visibly and retain successful run links on partial matrix failures
- [ ] Make retries idempotent so they do not create duplicate logical experiments/runs

## Acceptance criteria

- [ ] Persist the expanded configuration matrix before execution with an explicit configured combination limit; a two-configuration experiment produces separate traceable runs.
- [ ] Chunk/embedding changes build compatible revisions before evaluation; query-only changes reuse compatible ready revisions. A failed reindex prevents that config from being evaluated against the wrong corpus.
- [ ] Invalid/unsupported combinations are rejected visibly, and partial matrix failures retain successful run links. Retries do not create duplicate logical experiments/runs.

## Verification

Two-config sweep including a chunk-size change; inspect different index identities and the same dataset/source corpus; controlled reindex failure and task retry; no hidden fallback to the old index.
