# RB-01 — Boot the local application stack

Part of [Sprint 1 — Runnable foundation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Done

**Sprint:** Sprint 1 — Runnable foundation

**Priority / Size / Owner:** P0 · L · platform/backend

**Depends on:** none

## User story

As a developer, I can start the required services locally so implementation can be exercised against the intended architecture.

## Scope

Replace the banner in `backend/cmd/api/main.go` with an HTTP lifecycle; add backend/frontend Dockerfiles and minimal Vue/Vite entry point; complete `docker-compose.yml` with Airflow initialization, required runtime components, DAG/shared-file mounts, and service readiness; retain `scripts/dev.sh` as the shell launcher. Configure separate Airflow metadata and application database ownership.

## Tasks

- [x] Replace the banner in `backend/cmd/api/main.go` with an HTTP server lifecycle (startup and graceful shutdown)
- [x] Add backend and frontend Dockerfiles and a minimal Vue/Vite entry point
- [x] Complete `docker-compose.yml` with Airflow initialization, required runtime components, DAG/shared-file mounts, and service readiness
- [x] Implement proposed `/healthz` reporting process health and `/readyz` reporting database/schema readiness (non-success when unavailable)
- [x] Configure separate Airflow metadata and application database ownership
- [x] Document required environment settings and local credentials, keeping provider keys uncommitted; make startup errors identify the failed service/dependency
- [x] Retain `scripts/dev.sh` as the shell launcher

## Acceptance criteria

- [x] `sh scripts/dev.sh` builds and starts a reachable API and Vue page, PostgreSQL with pgvector, and Airflow capable of loading and executing DAGs; an idle Airflow image alone is not completion.
- [x] Proposed `/healthz` reports process health; `/readyz` reports database/schema readiness and returns a non-success status when unavailable.
- [x] Required environment settings and local credentials are documented; provider keys are not committed. Startup errors identify the failed service/dependency.

## Verification

Clean disposable Compose environment; HTTP health checks and browser page load; execute a non-provider Airflow connectivity task; remove that temporary verification task afterward. Restart services and confirm shutdown/startup behaves predictably.

Verification checklist (to be completed during implementation):

- [x] Disposable Compose environment boots from clean state
- [x] HTTP health checks pass and browser page loads
- [x] A non-provider Airflow connectivity task executes (and is removed afterward)
- [x] Services restart with predictable shutdown/startup behavior
