# RB-05 — Upload and dispatch documents

Part of [Sprint 2 — Document library](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 2 — Document library

**Priority / Size / Owner:** P0 · M · backend

**Depends on:** [RB-02.md](RB-02.md), [RB-03.md](RB-03.md)

## User story

As a developer/evaluator, I can upload a document and receive its queued identity so processing can begin asynchronously.

## Scope

Implement `POST /api/v1/documents`, list/detail routes, durable metadata and shared-volume storage; validate allowed files and configured size bounds; associate ingestion config and trigger `document_ingestion` in Airflow. Persist dispatch correlation and errors.

## Tasks

- [ ] Implement `POST /api/v1/documents` plus list/detail routes
- [ ] Store durable document metadata and uploaded bytes on the shared volume
- [ ] Validate allowed file formats and the configured size bound
- [ ] Associate the ingestion config and trigger `document_ingestion` in Airflow via its supported API
- [ ] Persist dispatch correlation IDs, job/run state, and dispatch errors
- [ ] Return the persisted document with queued status for accepted uploads; keep the batch pipeline out of the synchronous request path
- [ ] Return documented errors for unsupported/oversized uploads and storage/dispatch failures; ensure partial uploads do not appear processed or leave unexplained records/files
- [ ] Prevent file names escaping the upload directory and duplicate/retried dispatch creating duplicate active ingestion for the same document revision

## Acceptance criteria

- [ ] Accepted PDF/DOCX/TXT uploads return the persisted document with queued status; Go does not perform the batch pipeline synchronously.
- [ ] Unsupported/oversized uploads and storage/dispatch failures return documented errors; partial uploads do not appear processed or leave unexplained records/files.
- [ ] File names cannot escape the upload directory. Duplicate/retried dispatch cannot create duplicate active ingestion for the same document revision.

## Verification

HTTP multipart upload → queued database row and Airflow run; rejected format/size/path-name cases; unavailable Airflow produces a visible dispatch failure and a documented recovery path.

Verification checklist (to be completed during implementation):

- [ ] HTTP multipart upload produces a queued database row and an Airflow run
- [ ] Rejected format, size, and path-name cases return documented errors
- [ ] Unavailable Airflow produces a visible dispatch failure and a documented recovery path
