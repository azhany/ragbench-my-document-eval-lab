# RB-15 — Score retrieval and generation separately

Part of [Sprint 4 — Repeatable evaluation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 4 — Repeatable evaluation

**Priority / Size / Owner:** P0 · L · evaluation

**Depends on:** [RB-14 — Orchestrate durable evaluation runs](RB-14.md)

## User story

As an evaluator, I can distinguish retrieval quality, answer quality, and efficiency instead of receiving an unexplained combined score.

## Scope

Implement Recall@K and MRR, versioned answer-relevance and groundedness rubrics, citation correctness/evidence match, and operational aggregates in importable evaluation modules. Persist scoring configuration, judge outputs/errors, and evaluation cost separately from query cost.

## Tasks

- [ ] Implement Recall@K and MRR in importable evaluation modules, documenting deduplication, missing-relevance, and K semantics
- [ ] Add versioned answer-relevance and groundedness rubrics (versioned judge model, rubric, and policy)
- [ ] Implement citation correctness/evidence-match scoring
- [ ] Implement operational aggregates that include denominators, failure counts, and missing-score counts
- [ ] Persist scoring configuration, judge outputs/errors, and evaluation cost separately from query cost
- [ ] Treat judge failure as `evaluator_failed`, distinct from low quality, with an explicit p50/p95 method and successful/failed request populations

## Acceptance criteria

- [ ] Recall@K is relevant evidence retrieved within K divided by total expected evidence at the configured relevance unit; MRR uses the first relevant rank. Deduplication, missing relevance, and K semantics are documented.
- [ ] Each result stores separate retrieval, generation, citation, timing, token, and cost metrics. Aggregates include denominators, failure counts, and missing-score counts; undefined values do not become zero or perfect scores.
- [ ] Judge failure is `evaluator_failed`, distinct from low quality. p50/p95 method and successful/failed request populations are explicit. Judge model, rubric, and policy are versioned.

## Verification

Hand-calculated Recall@K/MRR cases, duplicates/empty/missing judgments, percentile/aggregate fixtures, and controlled judge failures; a small real scoring run produces inspectable rationale and separate evaluator cost.
