# RB-16 — Run and inspect evaluations in the UI

Part of [Sprint 4 — Repeatable evaluation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 4 — Repeatable evaluation

**Priority / Size / Owner:** P1 · M · frontend

**Depends on:** [RB-12 — Deliver the evidence-connected Chat screen](RB-12.md), [RB-15 — Score retrieval and generation separately](RB-15.md)

## User story

As an evaluator, I can select a dataset/config, launch a run, and inspect individual failures so evaluation is usable without database access.

## Scope

Build Evaluations dataset/config selectors, run action/status, aggregate cards, per-question answer/evidence/score views, and trace links. Add dataset import/versioned-edit controls against RB-13 contracts.

## Tasks

- [ ] Build Evaluations dataset and config selectors on the existing API client
- [ ] Implement run launch action and accurate run status display (terminal or partial state, no fake progress)
- [ ] Build aggregate cards that keep quality, efficiency, and failure counts separate
- [ ] Build per-question answer/evidence/score views with links to each case's evidence and trace
- [ ] Add dataset import and versioned-edit controls against the [RB-13](RB-13.md) contracts
- [ ] Keep invalid dataset, failed launch, missing score, and failed case states visible after reload

## Acceptance criteria

- [ ] A versioned dataset can be maintained and selected; a launched run reaches an accurate terminal or partial state without fake progress.
- [ ] Aggregate cards keep quality, efficiency, and failure counts separate; each case leads to its evidence and trace.
- [ ] Invalid dataset, failed launch, missing score, and failed case states remain visible after reload.

## Verification

Browser import/edit dataset, launch the 20–40-case golden run, reload during execution, and inspect one successful and one controlled failed/scoring-error case.
