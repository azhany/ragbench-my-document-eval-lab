Part of [Sprint 3 — Traceable chat](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

## User story

As a reviewer, I can move from question to evidence to answer to metrics to trace without manually inspecting API payloads.

## Scope

Build question composer/config selection, answer display, citation cards, optional retrieved-context drawer, and latency/token/cost summary with trace navigation. Document how the drawer gets context from the trace/detail contract.

## Tasks

- [x] Build the question composer with config selection
- [x] Build the answer display and citation cards
- [x] Build the optional retrieved-context drawer, documenting how it gets context from the trace/detail contract
- [x] Build the latency/token/cost summary with trace navigation
- [x] Implement distinct UI states for empty retrieval, loading, provider failure, and unavailable cost
- [x] Render citation text safely
- [x] Make reopening a trace show the evidence/config used at that time, not whatever is currently active

## Acceptance criteria

- [ ] A submitted question displays the real answer, source snippets, selected config, and persisted trace metadata; the successful provider/browser walkthrough remains outstanding.
- [x] Empty retrieval, loading, provider failure, and unavailable cost have distinct UI states. Citation text is rendered safely.
- [x] Reopening a trace shows the evidence/config used then, not whatever document/config is currently active.

## Verification

Browser-drive successful chat, open citations/context/trace, then exercise insufficient evidence and a controlled provider error; verify displayed values match the returned trace.

Verification checklist (to be completed during implementation):

- [ ] Successful chat browser-driven; citations/context/trace opened
- [ ] Insufficient-evidence state exercised in the browser
- [x] Controlled provider error exercised in the browser against the live API
- [ ] Displayed values verified against the returned trace for a successful chat
