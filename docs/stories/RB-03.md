# RB-03 — Persist immutable RAG configurations

Part of [Sprint 1 — Runnable foundation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 1 — Runnable foundation

**Priority / Size / Owner:** P0 · M · backend

**Depends on:** [RB-02.md](RB-02.md)

## User story

As an evaluator, I can save a named configuration so runs can reproduce the settings I selected.

## Scope

Migrate `rag_configs`; implement proposed create/list/detail config APIs in Go; persist chunk size/overlap, top-k, vector/hybrid mode, rerank flag, prompt version, model profile, and embedding identity. Define the small provider interfaces and immutable prompt/model references consumed later.

## Tasks

- [ ] Add the `rag_configs` migration
- [ ] Implement the proposed create/list/detail config APIs in Go
- [ ] Persist chunk size/overlap, top-k, vector/hybrid mode, rerank flag, prompt version, model profile, and embedding identity
- [ ] Define the small provider interfaces and immutable prompt/model references consumed by later stories
- [ ] Reject invalid chunk bounds, overlap not smaller than size, invalid top-k, and unknown profiles/versions with structured errors
- [ ] Reject hybrid/rerank-enabled execution as unavailable until [RB-17.md](RB-17.md)/[RB-25.md](RB-25.md) lands — never silently treat it as vector/no-rerank
- [ ] Publish the request/response/error contracts in [API.md](../API.md)

## Acceptance criteria

- [ ] Valid configurations survive restart; changing settings creates a new immutable identity rather than changing past runs.
- [ ] Reject invalid chunk bounds, overlap not smaller than size, invalid top-k, and unknown profiles/versions with structured errors.
- [ ] Unsupported capabilities are explicit. Until [RB-17.md](RB-17.md)/[RB-25.md](RB-25.md) lands, hybrid/rerank-enabled execution is rejected as unavailable, never silently treated as vector/no-rerank.

## Verification

API persistence checks; boundary tests for config validation and a historical-config immutability test. Publish request/response/error contracts in [API.md](../API.md).
