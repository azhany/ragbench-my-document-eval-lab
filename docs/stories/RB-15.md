## User story

As an evaluator, I can distinguish retrieval quality, answer quality, and efficiency instead of receiving an unexplained combined score.

## Scope

Implement Recall@K and MRR, versioned answer-relevance and groundedness rubrics, citation correctness/evidence match, and operational aggregates in importable evaluation modules. Persist scoring configuration, judge outputs/errors, and evaluation cost separately from query cost.

## Tasks

- [x] Implement Recall@K and MRR in importable evaluation modules, documenting deduplication, missing-relevance, and K semantics
- [x] Add versioned answer-relevance and groundedness rubrics (versioned judge model, rubric, and policy)
- [x] Implement citation correctness/evidence-match scoring
- [x] Implement operational aggregates that include denominators, failure counts, and missing-score counts
- [x] Persist scoring configuration, judge outputs/errors, and evaluation cost separately from query cost
- [x] Treat judge failure as `evaluator_failed`, distinct from low quality, with an explicit p50/p95 method and successful/failed request populations

## Acceptance criteria

- [x] Recall@K is relevant evidence retrieved within K divided by total expected evidence at the configured relevance unit; MRR uses the first relevant rank. Deduplication, missing relevance, and K semantics are documented.
- [x] Each result stores separate retrieval, generation, citation, timing, token, and cost metrics. Aggregates include denominators, failure counts, and missing-score counts; undefined values do not become zero or perfect scores.
- [x] Judge failure is `evaluator_failed`, distinct from low quality. p50/p95 method and successful/failed request populations are explicit. Judge model, rubric, and policy are versioned.
