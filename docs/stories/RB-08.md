## User story

As a developer/evaluator, I can inspect, reprocess, and delete documents from Library so the indexed corpus stays manageable.

## Scope

Implement Library upload/table/status/chunk-count/error views; `POST /api/v1/documents/{id}/reprocess`, `DELETE /api/v1/documents/{id}`; implement `document_reindex` using shared ingestion stages. Define active revision switching and retention semantics.

## Tasks

- [x] Implement Library upload/table/status/chunk-count/error views
- [x] Implement `POST /api/v1/documents/{id}/reprocess`
- [x] Implement `DELETE /api/v1/documents/{id}`
- [x] Implement `document_reindex` using the shared ingestion stages
- [x] Define active revision switching and retention semantics
- [x] Make reprocess create and activate a new ready revision only after success; preserve the previous usable revision and report the new failure when reprocessing fails
- [x] Make delete remove the document from new retrieval and handle in-flight tasks without resurrection, while historical trace evidence stays readable under the documented retention policy
- [x] Define documented behavior for invalid IDs and repeated actions

## Acceptance criteria

- [x] UI shows queued/processing/processed/failed states, chunk counts, and the actual error; reprocess creates and activates a new ready revision only after success.
- [x] Failed reprocessing preserves the previous usable revision and reports the new failure. Delete removes the document from new retrieval and handles in-flight tasks without resurrection.
- [x] Historical trace evidence remains readable under the documented retention policy; invalid IDs and repeated actions have documented behavior.
