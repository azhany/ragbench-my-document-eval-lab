# RB-34 — Build RAG configurations from the Settings UI

Part of Sprint 8 — Settings-managed RAG workspace. This story inherits the
shared definition of ready and done in `docs/SPRINT_PLAN.md`.

**Status:** Implemented; frontend tests and production build pass

**Sprint:** Sprint 8 — Settings-managed RAG workspace

**Priority / Size / Owner:** P0 · M · product + frontend

## User story

As a RAGbench operator, I can configure chunking, retrieval, reranking,
prompt, generation, and embedding settings in one Settings screen and save a
reproducible configuration for downstream workflows.

## Tasks

- [x] Add the Settings route and RAG configuration builder
- [x] Populate model and embedding selectors from the backend catalog rather
  than a second frontend model allowlist
- [x] Persist hybrid RRF and reranking settings through the existing immutable
  configuration API
- [x] Show a live run-identity preview and the immutable-history behavior
- [x] Keep empty, loading, validation, conflict, and backend failure states
  visible and actionable
- [x] Link Library, Chat, Evaluations, and Experiments setup guidance to
  Settings
- [x] Add focused Settings UI tests for loading, save, profile creation, and
  API failure

## Acceptance criteria

- [x] An operator can save a complete RAG configuration without curl or a
  database console.
- [x] The saved configuration appears in the UI and remains compatible with
  existing Library/Chat/Evaluation selectors.
- [x] Changing a setting requires a new configuration name; historical
  configuration identities are not edited in place.
- [x] Credentials never enter browser state or the request payload.

## Verification

Run `npm test` and `npm run build`; browser-verify the happy path against a
migrated Compose stack with at least one seeded provider profile.
