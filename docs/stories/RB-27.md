# RB-27 — Accept financial PDFs and images for document intelligence

Part of Sprint 7 — Document intelligence assessment. This story inherits the shared definition of ready and done in `docs/SPRINT_PLAN.md`.

**Status:** Not started

**Sprint:** Sprint 7 — Document intelligence assessment

**Priority / Size / Owner:** P0 · M · backend + pipeline

**Depends on:** RB-05, RB-06

## User story

As an assessment reviewer, I can upload a financial PDF or image and receive a durable document/analysis identity so the document-intelligence workflow can run asynchronously and failures remain inspectable.

## Scope

Reuse the existing document storage/status/dispatch model. Extend accepted assessment input to JPG/PNG and add an OCR/vision extraction path while retaining the current text-bearing PDF path. Do not weaken existing filename, size, durability, or failure guarantees.

## Tasks

- [ ] Define the assessment-facing upload/result API contract and analysis-run identity
- [ ] Accept PDF plus JPG/PNG financial documents with explicit byte/type limits
- [ ] Reuse durable source storage and document identity rather than creating a second file store
- [ ] Route text-bearing PDFs through the existing parser where practical
- [ ] Add bounded OCR/vision extraction for images
- [ ] Persist extraction method, status, raw text/evidence reference, timing, and classified failure
- [ ] Add representative invoice/receipt fixtures and corrupt/unsupported fixtures
- [ ] Update API documentation and `ENGINEERING_NOTES.md`

## Acceptance criteria

- [ ] A supported PDF and supported JPG/PNG each receive durable identity and reach extracted/processing state through the real workflow.
- [ ] Unsupported, oversized, corrupt, and unreadable inputs fail visibly without appearing successfully processed.
- [ ] Extraction evidence is linked to the original immutable document/revision identity.
- [ ] Existing RAG document behavior remains backward compatible.

## Verification

Record runtime evidence in `docs/SPRINT_7_VERIFICATION.md`: multipart upload, extraction output, image path, visible failure, persistence after restart.
