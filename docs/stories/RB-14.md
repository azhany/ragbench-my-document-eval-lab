# RB-14 — Orchestrate durable evaluation runs

Part of [Sprint 4 — Repeatable evaluation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 4 — Repeatable evaluation

**Priority / Size / Owner:** P0 · L · backend/pipeline

**Depends on:** [RB-13 — Maintain a versioned golden dataset](RB-13.md)

## User story

As an evaluator, I can launch a dataset against a named config so every case uses the normal Go query pipeline.

## Scope

Migrate `eval_runs`/`eval_results`; implement create/list/detail/results APIs and `rag_evaluation` DAG. Go exposes the same query path with evaluation request attribution; Airflow calls it per case and records run/result/trace relationships.

## Tasks

- [ ] Add numbered migrations for `eval_runs` and `eval_results` under `db/migrations/`, pinning dataset, config, corpus/index revision, and evaluator policy per run
- [ ] Implement evaluation run create/list/detail/results APIs in Go
- [ ] Expose the normal Go query path with evaluation request attribution so evaluation cases run through the same pipeline as chat
- [ ] Implement `rag_evaluation` DAG dispatch: call the Go API per case and record run/result/trace relationships
- [ ] Make case/task retries idempotent so completed results are not duplicated
- [ ] Track per-case status and aggregate run status that distinguish completed, partial, and failed work
- [ ] Surface Airflow dispatch failure as a visible run failure, never as successful processing

## Acceptance criteria

- [ ] Run creation pins dataset, config, corpus/index revision, and evaluator policy; every attempted case has status and a query trace or explicit pre-query failure.
- [ ] Retries do not duplicate completed results. A case/provider failure remains visible; run status and aggregation distinguish completed, partial, and failed work.
- [ ] Airflow dispatch failure is surfaced; Python does not duplicate retrieval, prompt construction, or generation logic.

## Verification

Small dataset DAG smoke run through real Go API; one injected failed case and one retried task; verify run status, unique results, trace links, and immutable inputs in PostgreSQL.
