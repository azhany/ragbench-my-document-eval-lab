# RB-25 — Enable real reranking as an experiment dimension

Part of the [optional backlog](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Optional backlog — not required for the six-sprint core gate; not committed

**Priority / Size / Owner:** P2 · M · backend/evaluation

**Depends on:** [RB-17 — Add configurable hybrid retrieval](RB-17.md), [RB-19 — Compare runs with persisted regression policy](RB-19.md)

## User story

As an evaluator, I can measure whether reranking improves evidence quality enough to justify its latency/cost.

## Scope

Select a real supported reranker behind a small interface; persist reranker profile, candidate limit, and configuration; expose the on/off setting through RB-18/RB-20 once executable.

## Tasks

- [ ] Select a real supported reranker behind a small interface
- [ ] Persist reranker profile, candidate limit, and configuration
- [ ] Record a rerank span, usage/cost when applicable, and final order for enabled runs; disabled runs skip the call
- [ ] Make reranker failures visible rather than silently falling back to vector/hybrid results
- [ ] Expose the on/off setting through [RB-18](RB-18.md)/[RB-20](RB-20.md) once reranking is executable

## Acceptance criteria

- [ ] Enabled runs actually rerank retrieved candidates and record a rerank span, usage/cost when applicable, and final order. Disabled runs skip the call.
- [ ] Reranker failures are visible, not silent vector/hybrid fallbacks.

## Verification

Deterministic ordering/on-off/failure tests plus a small authorized reranked evaluation comparison. If pulled into Sprint 5, reserve capacity explicitly; do not claim rerank support before this story lands.
