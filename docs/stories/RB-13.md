# RB-13 — Maintain a versioned golden dataset

Part of [Sprint 4 — Repeatable evaluation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 4 — Repeatable evaluation

**Priority / Size / Owner:** P0 · M · evaluation/backend

**Depends on:** [RB-08.md](RB-08.md), [RB-11.md](RB-11.md)

## User story

As an evaluator, I can maintain 20–40 questions with expected evidence and reference answers so comparisons use a stable benchmark.

## Scope

Migrate `eval_datasets` and `eval_cases`; implement proposed dataset create/import/list/detail and versioned case-edit APIs; prepare a small lawful local corpus and reviewed golden cases. Validate references and pin source/relevance policy.

## Tasks

- [ ] Add migrations for `eval_datasets` and `eval_cases`
- [ ] Implement the proposed dataset create/import/list/detail APIs
- [ ] Implement versioned case-edit APIs
- [ ] Prepare a small lawful local corpus and reviewed golden cases (20–40 for the demonstration)
- [ ] Validate expected-evidence references and pin the source/relevance policy
- [ ] Make updating cases create a new version, with old runs retaining their original cases
- [ ] Reject invalid references and empty/unusable datasets
- [ ] Use a documented stable relevance unit or explicit remapping across chunk configurations; never treat old chunk UUIDs as ground truth for a different index revision

## Acceptance criteria

- [ ] A dataset version contains 20–40 reviewed cases for the demonstration, with question, reference answer, and expected document/chunk or mapped source evidence.
- [ ] Updating cases creates a new version; old runs retain their original cases. Invalid references and empty/unusable datasets are rejected.
- [ ] Different chunk configurations use a documented stable relevance unit or explicit remapping; old chunk UUIDs are not treated as ground truth for a different index revision.

## Verification

Import and read back the golden dataset; invalid-reference and version-immutability tests; inspect representative source evidence against reference answers.

Verification checklist (to be completed during implementation):

- [ ] Golden dataset imported and read back
- [ ] Invalid-reference tests pass
- [ ] Version-immutability tests pass
- [ ] Representative source evidence inspected against reference answers
