# RB-28 — Extract schema-valid financial data with the LLM

Part of Sprint 7 — Document intelligence assessment. This story inherits the shared definition of ready and done in `docs/SPRINT_PLAN.md`.

**Status:** Implemented; unit/fixture and live classified provider-failure paths verified; provider success pending

**Sprint:** Sprint 7 — Document intelligence assessment

**Priority / Size / Owner:** P0 · M · backend

**Depends on:** RB-27 and the existing model/provider abstraction

## User story

As an assessment reviewer, I can inspect normalized financial fields extracted from document evidence and distinguish absent evidence, malformed model output, and provider failure.

## Scope

Introduce a versioned financial-document schema and prompt. Convert extracted evidence into structured invoice/receipt data using the existing model-provider abstraction. Validate model output against the schema before it can enter business validation or reporting.

## Tasks

- [x] Define versioned types for document type, vendor, document/invoice number, invoice date, due date, currency, subtotal/tax/total where available, and line items
- [x] Define explicit nullable/unknown semantics for unsupported or absent fields
- [x] Create a versioned extraction prompt that instructs the model to use document evidence only
- [x] Request structured JSON/output mode where the selected provider supports it
- [x] Parse and schema-validate model output
- [x] Persist prompt/model/schema identity with the extraction result
- [x] Implement bounded handling for malformed output and provider errors
- [x] Add unit/fixture tests for valid, missing-field, malformed, and unexpected-field outputs
- [x] Record prompt-design decisions and limitations in `ENGINEERING_NOTES.md`

## Acceptance criteria

- [x] Successful extraction produces schema-valid normalized data linked to the source document and raw extraction evidence.
- [x] Missing evidence is represented explicitly; the workflow does not silently invent mandatory values.
- [x] Malformed model output and provider failures are visible, classified, and cannot masquerade as valid structured data.
- [x] Prompt/model/schema versions are reconstructible from persisted result/trace data.

## Verification

Use at least two financial fixtures with different layouts and one controlled malformed/provider-failure path. Record evidence in `docs/SPRINT_7_VERIFICATION.md`.
