# RB-31 — Trace, evaluate, and guard the document-intelligence workflow

Part of Sprint 7 — Document intelligence assessment. This story inherits the shared definition of ready and done in `docs/SPRINT_PLAN.md`.

**Status:** Not started

**Sprint:** Sprint 7 — Document intelligence assessment

**Priority / Size / Owner:** P1 · M · backend + evaluation

**Depends on:** RB-30; reuses RB-11 and the existing evaluation/monitoring foundation

## User story

As an assessment reviewer, I can inspect latency, usage, failures, guardrail outcomes, and repeatable extraction quality rather than trusting a single demo document.

## Scope

Reuse the lab's tracing/evaluation philosophy for the new workflow. Add only metrics that explain structured extraction and validation quality. Historical-invoice RAG comparison is an optional bonus and must not be coupled to primary extraction correctness.

## Tasks

- [ ] Add spans/tool events for extraction/OCR, structured extraction, validation, and summary
- [ ] Record total/per-stage processing time and provider usage/tokens when reported
- [ ] Reuse explicit cost known/unknown semantics rather than assuming zero cost
- [ ] Add bounded retry metadata and stable failure taxonomy
- [ ] Add confidence metadata only where its meaning is documented; do not manufacture a pseudo-probability from model prose
- [ ] Create a small labeled financial-document evaluation set with expected key fields/totals
- [ ] Score field-level/schema validity and validation detection separately from latency/cost
- [ ] Optional: reuse RAG to compare the current extracted document with previous documents from the same vendor, preserving citations
- [ ] Document guardrail/evaluation limits in `ENGINEERING_NOTES.md`

## Acceptance criteria

- [ ] A reviewer can attribute total processing time to workflow stages and correlate failures to a document/analysis run.
- [ ] Usage/cost reporting is truthful when provider usage or pricing is unavailable.
- [ ] Evaluation distinguishes extraction quality from deterministic validation outcomes and operational performance.
- [ ] Optional RAG comparison cannot overwrite or conceal the primary structured extraction result.
