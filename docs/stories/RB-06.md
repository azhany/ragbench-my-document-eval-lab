# RB-06 — Extract, normalize, and chunk source content

Part of [Sprint 2 — Document library](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Sprint 2 — Document library

**Priority / Size / Owner:** P0 · L · pipeline

**Depends on:** [RB-05.md](RB-05.md)

## User story

As a reviewer, I can rely on processed chunks retaining source identity so answers can cite the original evidence.

## Scope

Implement extraction/normalization/chunking stages in `airflow/dags/` with reusable Python modules; support text-bearing PDF, DOCX, TXT; retain page/section or available location metadata and deterministic chunk ordering for each revision.

## Tasks

- [ ] Implement extraction, normalization, and chunking stages in `airflow/dags/` as reusable Python modules
- [ ] Support text-bearing PDF, DOCX, and TXT inputs
- [ ] Retain page/section or available location metadata and deterministic chunk ordering for each revision
- [ ] Produce nonempty ordered chunks using the persisted size/overlap settings and a documented chunk unit
- [ ] End corrupt, encrypted, image-only, or empty extracted content in a visible classified failure — not a processed document with zero useful content
- [ ] Make task retry idempotent so retrying does not duplicate chunks
- [ ] Ensure a changed chunk configuration creates a new revision and cannot overwrite historical evidence identity

## Acceptance criteria

- [ ] All three formats produce nonempty ordered chunks using persisted size/overlap settings and a documented unit.
- [ ] Corrupt, encrypted, image-only, or empty extracted content ends in a visible classified failure, not a processed document with zero useful content.
- [ ] Retrying a task does not duplicate chunks; a changed chunk configuration cannot overwrite historical evidence identity.

## Verification

Small representative fixtures for all three formats; exact chunk boundary/overlap tests; corrupt/empty extraction tests; retry the same task and confirm stable revision/chunk identity.

Verification checklist (to be completed during implementation):

- [ ] Representative fixtures processed for PDF, DOCX, and TXT
- [ ] Exact chunk boundary/overlap tests pass
- [ ] Corrupt/empty extraction tests pass
- [ ] Task retry confirms stable revision/chunk identity
