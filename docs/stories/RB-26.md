# RB-26 — Add graded nDCG@K scoring

Part of the [optional backlog](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Not started

**Sprint:** Optional backlog — not required for the six-sprint core gate; not committed

**Priority / Size / Owner:** P2 · M · evaluation

**Depends on:** [RB-15 — Score retrieval and generation separately](RB-15.md), [RB-19 — Compare runs with persisted regression policy](RB-19.md)

## User story

As an evaluator, I can assess ranked evidence with graded relevance when binary relevance is insufficient.

## Scope

Add versioned graded judgments, documented gain/discount/normalization policy, per-case/aggregate nDCG@K, and comparison/UI exposure without replacing Recall@K or MRR.

## Tasks

- [ ] Add versioned graded judgments for cases that need graded relevance
- [ ] Document the gain/discount/normalization policy, including missing-judgment and zero-ideal-gain handling
- [ ] Implement per-case and aggregate nDCG@K in the evaluation modules
- [ ] Expose nDCG@K through comparison and UI without replacing Recall@K or MRR
- [ ] Prevent silently comparing runs that use different judgment/scoring policies

## Acceptance criteria

- [ ] Scores match hand-calculated graded rankings; missing judgments and zero ideal gain have documented handling.
- [ ] Runs using different judgment/scoring policies are not silently compared.

## Verification

Hand-calculated ideal/reversed/tied/zero-gain fixtures and one real result display. Keep deferred unless the golden dataset actually needs graded relevance.
