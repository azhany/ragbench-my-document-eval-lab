# RB-03 — Persist immutable RAG configurations

Part of [Sprint 1 — Runnable foundation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Status:** Done

**Sprint:** Sprint 1 — Runnable foundation

**Priority / Size / Owner:** P0 · M · backend

**Depends on:** [RB-02.md](RB-02.md)

## User story

As an evaluator, I can save a named configuration so runs can reproduce the settings I selected.

## Scope

Migrate `rag_configs`; implement proposed create/list/detail config APIs in Go; persist chunk size/overlap, top-k, vector/hybrid mode, rerank flag, prompt version, model profile, and embedding identity. Define the small provider interfaces and immutable prompt/model references consumed later.

## Acceptance criteria

- [x] Valid configurations survive restart; changing settings creates a new immutable identity rather than changing past runs.
- [x] Reject invalid chunk bounds, overlap not smaller than size, invalid top-k, and unknown profiles/versions with structured errors.
- [x] Unsupported capabilities are explicit. Until [RB-17.md](RB-17.md)/[RB-25.md](RB-25.md) lands, hybrid/rerank-enabled execution is rejected as unavailable, never silently treated as vector/no-rerank.

## Verification

API persistence checks; boundary tests for config validation and a historical-config immutability test. Publish request/response/error contracts in [API.md](../API.md).

Verification checklist (completed 2026-09-14; backend unit tests plus integration tests against a disposable `pgvector/pgvector:pg16` container migrated with `sh scripts/migrate.sh`; live API exercised with curl on `:8090`):

- [x] API persistence checks pass (configuration survives restart) — created `smoke-baseline`/`smoke-hybrid` through `POST /api/v1/rag-configs` (201 + `Location`), restarted the PostgreSQL container, booted a fresh API process, and listed both configs unchanged.
- [x] Boundary tests for config validation pass — `internal/ragconfig/config_test.go` covers chunk bounds (0, negative, above max), overlap ≥ size, negative overlap, top-k 0/above max, unknown prompt/model/embedding profile, unknown retrieval mode, blank/oversized name, and all-violations-at-once reporting. `internal/httpapi/ragconfigs_test.go` covers the 400/409/404/500 error mapping and unknown-field rejection.
- [x] Historical-config immutability test passes — `TestConfigurationsAreImmutableIdentities` creates two configs with different settings, re-opens the store (restart simulation), and asserts both keep their exact settings with distinct identities; no update/delete path exists in the store API.
- [x] Request/response/error contracts published in `API.md` — POST/GET/GET-by-id with validation table, error envelope (`invalid_body`, `validation_failed`, `name_conflict`, `not_found`), `unavailable_capabilities` semantics, and the `422 capability_unavailable` execution rule for RB-09/RB-10/RB-14.

Additional implementation notes: `backend/internal/providers` defines the `Embedder`/`Generator` interfaces (consumed by RB-07/RB-10) and the immutable profile/prompt registries (unknown entries fail explicitly); `rag_configs` bounds in migration `0004` mirror the Go constants; embedding identity is resolved server-side and persisted with the profile key. Live API smoke run confirmed: 201 with Location, 400 `validation_failed` with per-field details, 409 `name_conflict`, 404 `not_found`, `unavailable_capabilities: ["hybrid_retrieval","rerank"]` for the hybrid+rerank config, and schema check still gating `/readyz` (RequiredVersion now 4).
