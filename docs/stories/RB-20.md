## User story

As an evaluator, I can see which configuration is better and by how much, including its cost/latency tradeoffs.

## Scope

Implement Experiments config creation/detail, bounded matrix launch/status, baseline selection, config diff, side-by-side metrics/deltas, regression reasons, and per-case drill-down from Evaluations.

## Tasks

- [x] Implement Experiments config creation and detail views
- [x] Implement bounded matrix launch and status views
- [x] Implement baseline selection and a visible config diff
- [x] Implement side-by-side metrics/deltas and regression-reason display, keeping quality and efficiency separate
- [x] Implement per-case drill-down from Evaluations into a run's case trace
- [x] Display reasons for incompatible comparisons, missing metrics, and partial experiments, with unambiguous delta units and metric direction
- [x] Identify optional reranking explicitly and only show it as active when the persisted executable setting is enabled

## Acceptance criteria

- [x] UI exposes all implemented PRD tuning fields and identifies the persisted reranking setting without implying it ran when disabled.
- [ ] Baseline and candidate dataset/config/index/policy identities are visible; quality and efficiency remain separate, including cases with no single overall winner.
- [ ] Incompatible comparisons, missing metrics, and partial experiments display their reason; delta units and metric direction are unambiguous.

## Verification

Browser-create two configs, launch a small experiment, compare runs, inspect a case trace, and attempt an incompatible comparison; check displayed deltas against API results.

API evidence is recorded for the two live configurations and failed sweep. The read-only Playwright re-verification confirmed the experiment list, failed matrix, and absence of undefined combination labels. The new frontend test also exercises both persisted identities, configuration differences, separate quality/efficiency groups, explicit metric direction/thresholds, and the no-single-winner state. The remaining blocker is data, not the renderer: the existing sweep has no two completed eval-run links, so the live comparison and its incompatible/partial result states cannot be honestly claimed without another provider-backed run.
