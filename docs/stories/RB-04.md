# RB-04 — Connect the Vue application shell

Part of [Sprint 1 — Runnable foundation](../SPRINT_PLAN.md#4-detailed-stories). This story inherits the shared [definition of ready and done](../SPRINT_PLAN.md#5-shared-definition-of-ready-and-done).

**Priority / Size / Owner:** P0 · S · frontend

**Depends on:** [RB-01.md](RB-01.md), [RB-03.md](RB-03.md)

## User story

As a user, I can open the application and see whether its backend is reachable before beginning a workflow.

## Scope

Create Vue navigation for Overview, Library, Chat, Evaluations, Experiments, Monitor; use one API client and a working config list. Unimplemented destinations remain explicitly unavailable until their stories land, without fake metrics or sample success states.

## Tasks

- [ ] Create Vue navigation for Overview, Library, Chat, Evaluations, Experiments, Monitor
- [ ] Implement one API client shared by the shell
- [ ] Implement a working config list backed by the running backend
- [ ] Keep unimplemented destinations explicitly unavailable — no fake metrics or sample success states
- [ ] Implement distinct loading, empty, and unavailable states
- [ ] Show an actionable error on backend failure instead of a blank page; keep model secrets out of browser configuration
- [ ] Keep state component-local except for proven shared needs

## Acceptance criteria

- [ ] Navigation and config data use the running backend; loading, empty, and unavailable states are distinct.
- [ ] A backend failure gives an actionable error instead of a blank page. No model secrets reach browser configuration.
- [ ] State remains component-local except for proven shared needs.

## Verification

Browser-drive navigation, retrieve a persisted configuration, and stop the API to observe the visible failure state.

Verification checklist (to be completed during implementation):

- [ ] Navigation browser-driven across all six destinations
- [ ] A persisted configuration retrieved and displayed
- [ ] API stopped and the visible failure state observed
